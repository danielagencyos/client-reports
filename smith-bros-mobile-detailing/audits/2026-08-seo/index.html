SEO Strengths

  • Ranking equity is protected by design. The rebuild preserves the old site's URL structure — /services/, /mobile-detailing/{city}, /mobile-ceramic-coating/{city}, /paint-protection-film/{city}, /cars/{make} — so existing links and rankings carry over with minimal redirects.
  • No doorway-page risk on the 141 city pages. Sampled ceramic-coating pages for Carlsbad and Encinitas are only ~48% similar even after neutralizing the city name — each page carries genuinely distinct copy, headings, and local references, which is the hard part of local SEO at this scale.
  • Metadata is unique and correctly sized. Every sampled page has its own title (37–69 characters) and meta description (79–163 characters), a production-domain canonical, and Open Graph tags including og:image.
  • Fully crawlable static output. Astro SSG, real HTML navigation, FAQs in native <details> elements present in source, valid XML sitemap with 184 URLs, sane robots.txt.
  • Performance signals favor good Core Web Vitals. AVIF/WebP images, below-fold lazy-loading with the hero exempted and prioritized, self-hosted fonts, essentially zero third-party scripts.
  • Correct staging hygiene. The mockup is noindexed with canonicals to production, so it can't be indexed against the client's live site during review.

Findings — In Priority Order

Numbered by recommended fix order. Items 1–3 should land before DNS cutover.

1

No structured data on any page

High impact§15

Zero JSON-LD across 184 pages. For a local service business the misses are the most valuable schema types there are: LocalBusiness (service area, hours, phone) site-wide, Service on service pages, FAQPage where the accordions already exist, and BreadcrumbList on sub-pages. The old Webflow site is unlikely to have this either — it's a net gain over the current site, not just parity.

Fix One Astro component per schema type, injected via the shared layouts — a single template change covers every page. Roughly a half-day of work.
2

No breadcrumbs despite a three-level, 184-URL architecture

High impact§2 · §12

City pages sit three levels deep (e.g. /mobile-ceramic-coating/carlsbad) with no breadcrumb trail. Breadcrumbs strengthen the internal hierarchy signals that help the migrated rankings settle, distribute link equity to the hub pages, and pair naturally with the BreadcrumbList schema from finding 1.

Fix A breadcrumb component in the Service/Location layouts, rendered as real links with schema markup. Same template pass as finding 1.
3

Every image is hotlinked from the client's old Webflow CDN

Launch blocker§13

All photography loads from cdn.prod.website-files.com — the CDN of the site being replaced. When the client cancels Webflow after migrating, every image breaks. It also costs image SEO: filenames are Webflow hashes (697e25c385b2eb…) rather than the descriptive names §13 calls for, and hotlinked assets never enter our control for resizing or format decisions.

Fix Download all assets, rename descriptively (ceramic-coating-tesla-san-diego.avif), self-host, and rewrite URLs — scriptable in one pass. Must land before the client cancels Webflow.
4

City slugs are inconsistent across service hubs

Medium§2

The same city gets different slugs depending on the hub: coronado vs coronado-ca, fallbrook vs fallbrook-ca, vista vs vista-ca, and mira-mar vs miramar (the latter is also a misspelling — the San Diego neighborhood is Miramar). If these mirror the old site's URLs, keep them for launch and note them; if any are new, this is the last cheap moment to standardize — after launch each rename costs a redirect.

Fix Diff each variant against the old site's sitemap. Match legacy slugs exactly where they exist; standardize (no -ca suffix, correct spellings) where the page is new.
5

Paint protection film hub covers 10 fewer cities than the other services

Opportunity§2 · §11

Mobile detailing, ceramic coating, and window tinting each cover 37–38 cities; PPF covers 28. Missing from PPF: Fallbrook, Lakeside, Maderas, Ramona, Rancho Peñasquitos, Rancho Santa Fe, San Marcos, Santa Luz, Santee, Tierrasanta, and Valley Center. Some of those (Rancho Santa Fe, Santa Luz) are exactly the high-value neighborhoods where PPF demand concentrates.

Fix Confirm whether the gap is intentional (service range) — if not, add the missing PPF city pages with the same unique-content standard as the existing ones, highest-value neighborhoods first.
6

Legacy copy carried over on the /cars/ pages

Medium§3 · §4

The Tesla page H1 reads "Preserve the Timeless Elegance of Your Tesla with Our Mobile Detailing Services!" — keyword buried at the end, and its meta description is thin at 79 characters. The newer templates get this right ("Mobile Ceramic Coating Services San Diego"); this looks like copy inherited from the old site.

Fix A copy sweep of the eight /cars/ pages: make + service + location up front in the H1, and descriptions expanded toward 120–160 characters.
7

Staging noindex is a manual launch step

Launch checklist

The noindex, nofollow tag is hardcoded in BaseLayout.astro with a "remove at launch" comment — correct today, invisible-to-Google if it ships. It isn't mentioned in the deploy instructions.

Fix Add to the launch checklist and DEPLOY.md, or gate it on the SITE_URL env var so production builds drop it automatically.

SEO Launch Checklist

In order. Items 1–4 before DNS cutover; 5–7 immediately after.

  1. Migrate all images off the Webflow CDN, rename descriptively, rewrite URLs (finding 3).
  2. Add structured data + breadcrumbs at the layout level (findings 1–2).
  3. Reconcile city slugs against the old site's sitemap and prepare 301s for any URL that changes (finding 4).
  4. Remove the noindex tag in BaseLayout.astro and confirm SITE_URL is production (finding 7).
  5. Submit the sitemap in Search Console and monitor coverage — the preserved URL structure should keep redirects minimal.
  6. Verify Core Web Vitals with PageSpeed Insights on the production domain (lab numbers couldn't be pulled during this audit — API quota).
  7. Sweep the /cars/ copy and decide on the PPF city-page expansion (findings 5–6).

Method

Audited against the SEO sections of the agency's "SEO and CRO Web Design Guidelines" on August 5, 2026. Raw HTML was fetched and inspected for seven templates on the live Vercel deploy: homepage, service page, location page, two ceramic-coating city pages (for duplicate-content comparison), vehicle page, and contact — plus robots.txt and the full 184-URL sitemap. Checks covered titles, meta descriptions, canonicals, robots directives, heading hierarchy, semantic regions, structured data, image formats/alt/filenames/lazy-loading, slug consistency across hubs, and cross-hub coverage. Content uniqueness was measured by text similarity between same-template city pages with city names neutralized. Lab Core Web Vitals were not measured (PageSpeed Insights anonymous quota exhausted); performance is scored on implementation signals in the markup.
